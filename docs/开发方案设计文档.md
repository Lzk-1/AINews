## 1. 技术选型

### 1.1 选型原则

| 原则 | 说明 |
|------|------|
| 最小可运行闭环 | 优先跑通全链路，后续按使用体验迭代 |
| 单文件零运维 | 数据库用 SQLite，备份只需 cp；后续可平滑迁移 PostgreSQL |
| Python 生态优先 | RSS 解析、正文抽取、LLM SDK 生态最成熟 |
| 异步优先 | 采集层全异步，支撑高并发抓取 |
| 配置驱动 | 信源、Prompt、阈值、推送渠道均通过配置文件管理 |

### 1.2 技术栈

| 层级 | 技术选型 | 备选方案 | 选型理由 |
|------|---------|---------|---------|
| 后端语言 | Python 3.12+ | Node.js/TypeScript | 采集生态最成熟，LLM SDK 最全 |
| Web 框架 | FastAPI | Flask / Django | 异步原生、自动 OpenAPI 文档、性能好 |
| ORM | SQLAlchemy 2.0 (async) | Tortoise ORM | 生态成熟，支持 SQLite → PostgreSQL 平滑迁移 |
| 数据库 | SQLite (aiosqlite) | PostgreSQL | 单文件零运维，千级文章量性能足够 |
| 向量存储 | ChromaDB (嵌入式) | pgvector / Qdrant | 纯 Python 嵌入式，零额外服务依赖 |
| 任务调度 | APScheduler | Celery / systemd timer | 单机够用，不引入消息队列 |
| RSS 解析 | feedparser | 自写 XML 解析 | 稳定，处理编码和日期格式省心 |
| 正文抽取 | trafilatura | newspaper3k / readability | 边缘页面更稳定 |
| HTML 解析 | selectolax + BeautifulSoup4 | lxml | 高速解析 + 容错 |
| LLM 接入 | OpenAI 兼容 SDK (openai-python) | LangChain | 轻量直接，避免框架开销 |
| Embedding | sentence-transformers (all-MiniLM-L6-v2) | OpenAI Embedding API | 本地运行，零成本 |
| 前端框架 | Next.js 15 (App Router) + React 19 + TypeScript | SvelteKit / Vue | 生态最大，SSR/SSG 性能好，组件库丰富 |
| UI 组件库 | shadcn/ui + Tailwind CSS | Ant Design / MUI | 可定制性强，不锁定设计系统 |
| 状态管理 | Zustand | Redux / Jotai | 轻量，无样板代码 |
| 邮件发送 | aiosmtplib | SendGrid API | 自托管，无第三方依赖 |
| 部署 | Docker Compose | systemd / K8s | 依赖隔离，迁移方便，单机足够 |

### 3.2 采集器设计（策略模式 + 模板方法）

```python
# backend/app/collectors/base.py

from abc import ABC, abstractmethod
from dataclasses import dataclass
from datetime import datetime

@dataclass
class RawItem:
    """采集器产出的原始数据项"""
    source_id: str          # 信源 ID
    source_name: str        # 信源名称
    title: str              # 标题
    url: str                # 原文链接
    content: str | None     # 正文（可选，部分源需二次抓取）
    published_at: datetime  # 发布时间
    author: str | None      # 作者
    score_hint: float | None  # 来源侧热度分（如 HN points）
    extra: dict              # 源特定扩展字段


class BaseFetcher(ABC):
    """采集器抽象基类 —— 模板方法模式"""

    def __init__(self, source_config: SourceConfig):
        self.config = source_config

    @property
    @abstractmethod
    def source_type(self) -> str: ...

    @abstractmethod
    async def fetch(self, now: datetime) -> list[RawItem]:
        """子类实现具体抓取逻辑"""
        ...

    # ---- 模板方法（子类直接复用）----

    async def _fetch_html(self, url: str) -> str:
        """HTML 抓取模板"""
        return await http_client.get_text(url)

    async def _fetch_json(self, url: str) -> dict:
        """JSON 抓取模板"""
        return await http_client.get_json(url)

    def _create_item(self, **kwargs) -> RawItem:
        """标准数据项工厂方法"""
        return RawItem(
            source_id=self.config.id,
            source_name=self.config.name,
            **kwargs,
        )
```

```python
# backend/app/collectors/registry.py —— 工厂注册表

class FetcherRegistry:
    _registry: dict[str, type[BaseFetcher]] = {}

    @classmethod
    def register(cls, source_type: str):
        """装饰器：注册采集器"""
        def decorator(fetcher_cls: type[BaseFetcher]):
            cls._registry[source_type] = fetcher_cls
            return fetcher_cls
        return decorator

    @classmethod
    def create(cls, config: SourceConfig) -> BaseFetcher:
        fetcher_cls = cls._registry.get(config.type)
        if not fetcher_cls:
            raise ValueError(f"Unknown source type: {config.type}")
        return fetcher_cls(config)


# 使用示例
@FetcherRegistry.register("rss")
class RSSFetcher(BaseFetcher):
    source_type = "rss"
    async def fetch(self, now: datetime) -> list[RawItem]:
        ...

@FetcherRegistry.register("hackernews")
class HNFetcher(BaseFetcher):
    source_type = "hackernews"
    async def fetch(self, now: datetime) -> list[RawItem]:
        ...
```

### 3.3 去重模块设计

```python
# backend/app/processors/dedup.py

class Deduplicator:
    """三级去重：URL → SimHash → 语义向量"""

    def __init__(self, db: AsyncSession, vector_store: ChromaDB):
        self.db = db
        self.vector_store = vector_store

    async def is_duplicate(self, item: RawItem) -> bool:
        # 第一级：URL 精确去重
        if await self._check_url(item.url):
            return True

        # 第二级：SimHash 标题去重（汉明距离 ≤3）
        simhash = compute_simhash(item.title)
        if await self._check_simhash(simhash, threshold=3):
            return True

        # 第三级：语义向量去重（余弦相似度 >0.85）
        embedding = await self._embed(item.title)
        if await self._check_vector(embedding, threshold=0.85):
            return True

        # 全部通过，记录指纹
        await self._record(item, simhash, embedding)
        return False
```

### 3.4 AI 评分模块设计

```python
# backend/app/ai/scorer.py

class AIScorer:
    """LLM 评分过滤"""

    SCORE_PROMPT = """\
你是一个 AI 技术资讯编辑。请对以下内容进行 0-10 分评分。

评分维度：
- 相关度 (0-3分)：与大模型/AI 技术的相关性
- 信息密度 (0-3分)：是否有实质性技术信息（非营销/情绪内容）
- 时效性 (0-2分)：是否为最新动态或有长效价值
- 影响力 (0-2分)：对开发者决策的直接影响程度

标题：{title}
来源：{source}
摘要：{content}

请返回 JSON：{{"score": <0-10>, "dimensions": {{"relevance": <0-3>, "density": <0-3>, "timeliness": <0-2>, "impact": <0-2>}}, "reason": "<一句话>"}}
"""

    def __init__(self, provider: LLMProvider, threshold: float = 6.0):
        self.provider = provider
        self.threshold = threshold

    async def score_batch(self, items: list[RawItem]) -> list[ScoreResult]:
        """批量评分"""
        results = []
        for item in items:
            try:
                result = await self.provider.complete(
                    prompt=self.SCORE_PROMPT.format(
                        title=item.title,
                        source=item.source_name,
                        content=item.content[:2000] if item.content else "",
                    ),
                    response_format="json",
                )
                score_data = json.loads(result)
                results.append(ScoreResult(
                    item=item,
                    score=score_data["score"],
                    dimensions=score_data["dimensions"],
                    reason=score_data["reason"],
                ))
            except Exception:
                # LLM 失败降级：使用规则评分
                results.append(await self._rule_based_score(item))
        return results

    async def _rule_based_score(self, item: RawItem) -> ScoreResult:
        """规则降级评分：加权关键词匹配"""
        KEYWORD_WEIGHTS = {
            "openai": 3.0, "claude": 3.0, "gpt": 2.5,
            "llm": 2.0, "transformer": 2.0, "agent": 2.0,
            "diffusion": 2.0, "rag": 1.5, "inference": 1.5,
            "fine-tune": 1.5, "gpu": 1.0, "pytorch": 1.0,
        }
        title_lower = item.title.lower()
        score = sum(w for kw, w in KEYWORD_WEIGHTS.items() if kw in title_lower)
        return ScoreResult(item=item, score=min(score, 10.0), ...)
```

## 头条深度

### {headline_title}

{headline_analysis}

    async def generate_daily_digest(self, date: date) -> str:

        # 2. 分类选取
        headline = self._pick_headline(articles)          # 评分最高 1 条
        selected = self._pick_selected(articles, n=8)     # 精选 8 条
        tools = self._pick_tools(articles, n=3)            # 工具类 3 条
        briefs = self._pick_briefs(articles, n=10)         # 快讯 10 条

        # 3. 头条背景增强
        if headline.score >= 8:
            headline.analysis = await self.enhancer.enhance(headline)

        # 4. 渲染模板

    async def push_digest(self, digest: str, date: date):

                await distributor.send(
                    subject=f"AI 资讯日报 · {date}",

            except Exception as e:

## 9. 设计决策记录

### ADR-001: 为什么选择 SQLite 而非 PostgreSQL

**背景**：MVP 阶段数据量预估在千级文章/月。
**决策**：使用 SQLite + aiosqlite。
**理由**：单文件零运维，备份只需 cp；千级数据量性能足够；通过 SQLAlchemy ORM 抽象，后续可一行配置切换 PostgreSQL。

### ADR-002: 为什么采集器用策略模式而非插件系统

**背景**：需要支持 8+ 种信源类型，未来可能更多。
**决策**：策略模式 + 模板方法 + 注册表工厂。
**理由**：新增信源只需实现 `fetch()` 方法并加装饰器注册；模板方法复用 HTTP 抓取逻辑；比插件系统更轻量，编译期即可发现错误。

### ADR-003: 为什么 AI 增强放在存储之后

**背景**：采集到的原始内容质量参差不齐。
**决策**：先入库去重，再做 AI 评分。
**理由**：避免对重复内容浪费 LLM 调用和 token；一条内容只处理一次，成本可控。

### ADR-004: 为什么选择 ChromaDB 嵌入式模式

**背景**：需要向量存储支持语义去重和搜索。
**决策**：使用 ChromaDB 嵌入式模式。
**理由**：纯 Python，无额外服务依赖；与 SQLite 一样零运维；数据量在万级向量时性能足够。

### ADR-005: 为什么 LLM 统一走 OpenAI 兼容接口

**背景**：需要支持 DeepSeek/GPT/Claude/Gemini/Ollama 等多模型。
**决策**：所有 Provider 通过 OpenAI 兼容 API 接入。
**理由**：DeepSeek、Doubao、Ollama 等均提供 OpenAI 兼容接口；Claude/Gemini 也有兼容层；统一接口降低维护成本，切换模型只需改配置。
