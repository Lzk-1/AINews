## 1. 项目概述

### 1.1 项目背景

AI 领域技术迭代极快，2026 年大模型（GPT-6 Astra、Gemini、Claude、Qwen 等）几乎每月都有实质性更新。开发者、技术管理者和 AI 从业者面临严重的**信息过载**问题：

- 信息源分散在 Hacker News、Reddit、X(Twitter)、GitHub Trending、arXiv、厂商官方博客、微信公众号等十余个平台
- 同一事件被多源转载，重复阅读浪费大量时间
- 真正有价值的深度内容被淹没在快讯和营销噪音中
- 英文内容存在语言障碍

经调研，一个人每天花 40 分钟浏览各信息源，一周消耗约 4.5 小时，而经过筛选加工的资讯可把有效信息获取时间压缩到每天 8 分钟以内。

### 1.2 产品定位

**AINews** 是一个 AI 驱动的大模型技术与应用资讯聚合平台，核心价值不是"抓取更多内容"，而是"帮用户少看废话"。

**一句话定义**：从多源采集 → 去重清洗 → AI 评分过滤 → 摘要增强 → 多渠道分发的 AI 资讯情报站。

### 1.3 目标用户

| 用户画像 | 核心诉求 | 使用场景 |
|---------|---------|---------|
| AI 开发者/工程师 | 快速获取技术选型参考、新工具、开源项目动态 | 每日早间 5-10 分钟快速浏览 |
| 技术管理者/CTO | 把握行业趋势，判断技术方向 | 定期查看日报/周报 |
| AI 产品经理 | 了解应用落地案例和竞品动态 | 按分类筛选阅读 |
| 研究者/学生 | 追踪论文动态和前沿进展 | 按主题/关键词订阅 |
| 独立开发者/创业者 | 发现机会和工具链变化 | 实时热点推送 |

### 1.4 核心价值主张

1. **精准筛选**：不是聚合器，是过滤器 —— AI 对每条内容 0-10 评分，只保留高价值内容
2. **多源立体**：官方渠道 + 社区聚合 + 技术媒体三层信源交叉验证
3. **背景增强**：不只告诉你"发生了什么"，还补充"为什么重要"和"社区怎么看"
4. **灵活分发**：Web 浏览 / 邮件日报 / IM 推送 / API 接入，按需选择
5. **零运维部署**：Docker Compose 一键部署，开机自启、故障自恢复

### 2.2 信息源管理（P0）

#### 2.2.1 信源分层架构

| 层级 | 信源类型 | 代表来源 | 抓取频率 | 作用 |
|------|---------|---------|---------|------|
| 第一层 | 官方渠道 | OpenAI Blog、Anthropic News、Google DeepMind Blog、NVIDIA Developer Blog、通义千问/智谱/百川官方 | 每 2 小时 | 获取一手发布信息 |
| 第二层 | 社区聚合 | Hacker News、Reddit (r/MachineLearning, r/LocalLLaMA)、X/Twitter AI KOL | 每 1 小时 | 获取社区讨论热度 |
| 第三层 | 技术媒体 | arXiv 新论文、GitHub Trending、Hugging Face 论文榜、机器之心、量子位、新智元 | 每 6 小时 | 获取学术与开源动态 |

#### 2.2.2 信源配置管理

- **FR-2.2.1**：支持通过配置文件（OPML/JSON）批量导入 RSS 订阅源
- **FR-2.2.2**：支持在 Web 管理后台增删改查信源，包括：名称、URL、类型、抓取频率、启用/禁用状态
- **FR-2.2.3**：支持信源分组管理（如"官方博客"、"学术论文"、"中文媒体"）
- **FR-2.2.4**：支持信源健康度监控，连续失败超过阈值自动禁用并告警
- **FR-2.2.5**：预置优质信源模板（参考 BestBlogs 的 400+ OPML），开箱即用

#### 2.2.3 采集器类型

| 采集器 | 技术方案 | 适配场景 |
|-------|---------|---------|
| RSS/Atom Fetcher | feedparser 解析 | 博客、期刊、行业媒体 |
| Hacker News Fetcher | Firebase API + Algolia API | HN 热门故事与高赞评论 |
| Reddit Fetcher | Reddit JSON API | subreddit 帖子与高赞评论 |
| GitHub Trending Fetcher | HTML 解析 + README 抓取 | 开源项目动态 |
| arXiv Fetcher | arXiv Atom API | 论文更新 |
| X/Twitter Fetcher | Nitter/RSSHub 间接抓取 | AI KOL 推文 |
| 微信公众号 Fetcher | RSSHub 订阅 | 中文 AI 媒体 |
| YouTube Fetcher | 视频信息 + 字幕抓取 | AI 技术视频 |

### 2.3 数据处理（P0）

#### 2.3.1 去重策略（三级去重）

- **FR-2.3.1 - URL 精确去重**：同一 URL 不重复入库
- **FR-2.3.2 - 标题相似度去重**：使用 SimHash 计算标题指纹，汉明距离 ≤3 视为重复
- **FR-2.3.3 - 语义去重**：使用轻量 Embedding 模型（如 all-MiniLM-L6-v2）计算向量相似度，余弦相似度 >0.85 视为重复，保留最早的一条
- **FR-2.3.4 - 跨日去重**：维护 7 天去重索引，同一事件不同日不重复推送

#### 2.3.2 正文抽取

- **FR-2.3.5**：使用 trafilatura 从 HTML 中提取正文，去除广告、导航、侧边栏等噪音
- **FR-2.3.6**：对 HN/Reddit 外链，通过 Jina Reader 拉取 Markdown 正文
- **FR-2.3.7**：正文长度截断（默认 8000 字符），超长内容分段处理

#### 2.3.3 语言处理

- **FR-2.3.8**：自动检测内容语言（中/英），英文标题自动翻译为中文
- **FR-2.3.9**：支持双语展示（原文 + 中文翻译）

### 2.4 AI 增强处理（P0）

#### 2.4.1 评分过滤

- **FR-2.4.1**：对每条内容，LLM 从以下维度进行 0-10 分评分：
  - **相关度**：与大模型/AI 技术的相关性
  - **信息密度**：内容是否有实质性技术信息（非营销/情绪内容）
  - **时效性**：是否为最新动态或有长效价值
  - **影响力**：对开发者决策的直接影响程度
- **FR-2.4.2**：支持配置评分阈值（默认 6.0），低于阈值的内容不进入最终输出
- **FR-2.4.3**：支持配置每日报文数量上限（默认 30 条），按评分排序取 Top N

#### 2.4.2 摘要生成

- **FR-2.4.4**：对通过评分的内容，生成 100 字以内的中文摘要，提取核心信息
- **FR-2.4.5**：摘要须遵守"冷静克制"原则，禁止使用"震撼""颠覆""革命性"等营销词汇
- **FR-2.4.6**：摘要必须包含可验证的事实信息，禁止 LLM 编造细节

#### 2.4.3 标签与分类

- **FR-2.4.7**：自动打分类标签，预设分类包括：
  - 大模型与基础理论
  - Agent 工程实践
  - AI 编程工具链
  - 多模态生成（图像/视频/音频）
  - AI 应用落地
  - 开源项目动态
  - 行业投融资
  - 论文与研究
- **FR-2.4.8**：提取 3-5 个关键词标签，用于索引和关联推荐

#### 2.4.4 背景增强

- **FR-2.4.9**：对高价值内容（评分 ≥8），LLM 补充背景信息：该项目为什么重要、与已有方案的区别、对开发者意味着什么
- **FR-2.4.10**：对 HN/Reddit 内容，收集并总结高赞评论中的技术讨论要点

### 2.5 数据存储（P0）

- **FR-2.5.1**：结构化存储文章数据（标题、摘要、原文链接、来源、发布时间、评分、标签、正文等）
- **FR-2.5.2**：建立向量化索引，支持语义搜索
- **FR-2.5.3**：维护去重指纹库（SimHash + 向量）
- **FR-2.5.4**：支持数据自动清理（默认保留 90 天，可配置）

### 2.6 分发与展示（P0/P1）

#### 2.6.1 Web 前端（P0）

- **FR-2.6.1**：资讯信息流展示，按时间倒序排列，支持按分类/标签/关键词筛选
- **FR-2.6.2**：每条资讯卡片展示：标题、摘要、来源、时间、评分、标签、原文链接
- **FR-2.6.3**：支持全文搜索（关键词 + 语义搜索）
- **FR-2.6.4**：支持深色/浅色主题切换
- **FR-2.6.5**：响应式设计，适配桌面和移动端
- **FR-2.6.6**：支持收藏文章（P1）

#### 2.6.2 日报生成与推送（P0）

- **FR-2.6.7**：每日定时生成日报，格式为结构化 Markdown，包含固定栏目：
  - 头条深度（1 条，300-500 字分析）
  - 精选资讯（5-8 条，每条 100-200 字要点）
  - 工具与资源（2-3 个开源项目/工具）
  - 一句话快讯（8-10 条，每条 ≤50 字）
- **FR-2.6.8**：日报推送渠道：
  - 邮件（支持订阅/退订）
  - 飞书群机器人
  - 钉钉群机器人
  - Discord Webhook
  - Slack Webhook
  - 自定义 Webhook

#### 2.6.3 实时热点推送（P1）

- **FR-2.6.9**：评分 ≥9 的实时热点，立即推送至已配置的 IM 渠道
- **FR-2.6.10**：支持配置免打扰时间段

#### 2.6.4 API 接口（P1）

- **FR-2.6.11**：提供 RESTful API，支持按时间/分类/标签/评分查询资讯
- **FR-2.6.12**：提供 API Key 认证
- **FR-2.6.13**：提供 MCP Server 接口，将抓取、评分、过滤、摘要等能力暴露为 MCP 工具

### 2.7 管理后台（P1）

- **FR-2.7.1**：信源管理（增删改查、启用/禁用、分组）
- **FR-2.7.2**：采集任务监控（运行状态、成功率、最近抓取时间）
- **FR-2.7.3**：LLM 配置管理（模型选择、API Key、评分阈值、摘要 Prompt 模板）
- **FR-2.7.4**：推送渠道配置管理
- **FR-2.7.5**：系统日志查看

## 3. 非功能需求

### 3.1 性能

| 指标 | 要求 |
|------|------|
| RSS 采集并发 | 支持 50+ 并发抓取 |
| 单次全量采集耗时 | ≤5 分钟（400 源） |
| LLM 评分延迟 | 单条 ≤3 秒，批量 ≤30 秒 |
| Web 页面首屏加载 | ≤2 秒 |
| API 响应时间 | ≤500ms（P95） |

### 3.2 可用性

- 系统可用性 ≥99%（单机部署目标）
- 采集器单源失败不影响整体流程，失败自动跳过并记录
- LLM API 调用失败自动重试（3 次），重试失败降级为规则评分
- 支持 systemd timer / Docker 自动重启

### 3.3 可扩展性

- 采集器采用策略模式，新增信源只需实现 Fetcher 接口并注册
- LLM 支持多 Provider 切换（OpenAI / Claude / Gemini / DeepSeek / Doubao / Ollama 本地模型）
- 推送渠道支持插件式扩展
- 存储层支持从 SQLite 平滑迁移至 PostgreSQL

### 3.4 安全性

- API Key / Webhook URL 等敏感信息通过环境变量管理，不硬编码
- API 接口支持 Rate Limiting
- Web 前端支持 XSS 防护
- 信源 URL 白名单校验，防止 SSRF

### 3.5 部署与运维

- 支持 Docker Compose 一键部署
- 支持 systemd timer 部署（Linux）
- 配置文件与代码分离，支持多环境配置
- 提供健康检查端点 `/health`

## 4. 优先级与里程碑

### 4.1 优先级定义

| 优先级 | 说明 | 里程碑 |
|-------|------|-------|
| P0 | 核心功能，MVP 必须包含 | M1 - MVP |
| P1 | 重要功能，MVP 后第一迭代 | M2 - 增强 |
| P2 | 锦上添花，后续迭代 | M3 - 优化 |

### 4.2 里程碑规划

| 里程碑 | 范围 | 核心交付 |
|-------|------|---------|
| M1 - MVP | P0 功能 | RSS 采集 + 去重 + AI 评分摘要 + Web 展示 + 日报邮件推送 |
| M2 - 增强 | P1 功能 | HN/Reddit/GitHub 采集器 + 背景增强 + IM 推送 + API 接口 + 管理后台 |
| M3 - 优化 | P2 功能 | 实时热点推送 + 语义搜索增强 + MCP Server + 多语言支持 |

## 6. 风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| X/Twitter 反爬限制 | 无法稳定抓取 KOL 推文 | 使用 Nitter/RSSHub 间接方案，或接入官方 API（付费） |
| 微信公众号抓取合规风险 | 法律风险 | 使用 RSSHub 公开订阅，不做硬采集；信息完整性可妥协 |
| LLM API 成本 | 月度费用不可控 | 支持 DeepSeek/Ollama 等低成本方案；批量处理减少调用次数；评分阈值过滤减少处理量 |
| 信源不稳定 | 采集中断 | 健康度监控 + 自动禁用 + 告警；多源交叉降低单源依赖 |
| 去重误判 | 漏掉重要内容 | 三级去重 + 人工审核白名单；跨日去重索引仅 7 天 |
